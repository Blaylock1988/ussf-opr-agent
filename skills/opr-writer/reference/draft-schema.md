## `_opr_work/career_profile.json` (the ratee's confirmed experience; drives career_review.md)
```json
{"experience": {
  "joint_experience": {"has": false, "detail": ""},
  "headquarters_staff": {"has": false, "detail": ""},
  "pentagon": {"has": false, "detail": ""},
  "indo_pacific": {"has": true, "detail": "exercise planning, 2026"},
  "deployments": {"has": true, "detail": "6-mo, AFCENT, 2022"}
},
 "duty_titles": [
  {"period": "2022", "title": "Crew Commander", "source": "SURF"},
  {"period": "2024", "title": "Flight Commander", "source": "OPR"}
]}
```
The keys match the `id`s in `board_priorities.json`. Only the ratee can answer these. OPR text that mentions the Joint Staff or a CCMD describes supporting work, not an assignment.

Field notes:
- `text` holds plain spaces and is what you edit. `fitted` is generated by `opr.py fit <draft.json> --write`, and it is what gets pasted into the form. `fit_hash` fingerprints `text` at fit time: if `fitted` changes while `text` didn't, it was hand-edited, and `check`/`fit`/`build` stop before the fit can drop the change. Move the change into `text`, then refit. If the user reports fixing a typo by hand, ask for the fix and make it in `text`.
- Every `acronyms` entry records the meaning *as used*. A common (Att 1) acronym used with its listed meaning needs no entry. An entry whose meaning differs from Att 1 (for example STO) forces a Sec X definition.
- `acronym_categories` records AFPC category approvals, which are judgment calls: organizations, weapons_platforms, office_symbols, ranks, symbols_measurements. When `define_category_acronyms` is true, any of these with a meaning in `acronyms` is still listed in Sec X.
- `settings.policies` holds unit-dependent rules (`allow` | `warn` | `forbid`). Ask the user; never assume one unit's answer.
- Strats default to placeholders `#[N]/[M] <group>`. Real numbers only come from the user. No bottom-half strat, except a primary that a strong secondary requires (`writing-rules.md` §3).
- `board` is written by `audience.py` and holds the promotion-board audience. `ledger[].career_field` marks out-of-field experience so it gets written in plain language.
- `proper_nouns` lists the words in exercise or program names so lint doesn't treat them as undefined acronyms.
- Keep `remarks` `null` to have Sec X generated automatically; `check`, the guard and `build` all regenerate it the same way, and `build` records the result in `remarks_auto`. Only a hand-written `remarks` string is linted as such.
- `ledger[].exact_numbers`: figures the user vetted as exact counts even though they look round (e.g. `"100"` networks). Lint then reports them as info instead of "reads as an estimate". Qualified forms (`over 100`, `100+`) are never cleared.
- Stratification placeholders are written as `#[N]/[M]`. Anything inside `[brackets]` (e.g. `[2,5xx]`, `[test date]`) is highlighted in the DOCX for the rating chain.
- **Never hand-edit `draft.json`** in an editor; it is engine state and hand edits break the micro-spacing fit. Change it through the skill and `opr.py`.
- `ratee.fitness_placement`: `box1` (default) | `remarks` | `both` | `none`. The DOCX prints `FITNESS SCORE: <score>` there.
- `alternates`: at least half the lines get good alternates, the Job Description and strat/push lines first. `opr.py fit --write` stores them already fitted. Each is audited against the whole OPR (lint rule `guard`).
- `spares`: 4 fitted performance bullets on page 2 that the user can swap in. They must be lint-clean against the current OPR: no reused verbs, numbers or ledger items.
- `settings.export_reports`: also write the ledger, research and record-review reports as DOCX in `Output/` (asked at intake; default `true`).
- `career_profile.duty_titles`: every duty title from the AMS SURF and prior OPRs, oldest first; `career_review.py` flags regressions.
- The SSN is never stored.
